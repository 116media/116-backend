# Frontend Integration

The frontend consumes the new endpoint through the existing clean-architecture layering:
generated API client → repository → use case → hook. The article-detail sidebar switches from
`getPromotedArticles` (a popularity proxy) to the real `getPopularArticles` endpoint.

Reference docs:

- `apps/frontend/docs/article-detail/11-popular-articles-sidebar.md` — the sidebar renders up
  to ~5 `ArticleSummaryDto` in an `ArticleCard.Horizontal` list, current article excluded.
- `apps/frontend/docs/article-detail/19-open-questions.md` — decision **D4** / question **Q3**:
  the sidebar approximates popularity with promoted articles because no true popularity
  endpoint exists; "when a real popularity-sorted endpoint (by engagement/views) lands, only
  the primary source swaps; the UI and mapping remain unchanged." This feature is that
  endpoint.

## 1. Regenerate the API client

The client is generated by **swagger-typescript-api** (not orval), via the package.json
script:

```
yarn api:generate
```

which runs:

```
yarn dlx swagger-typescript-api generate \
  -p http://localhost:5025/swagger/v1/swagger.json \
  -o ./src/shared/infrastructure/api/generated/ -n 116.api.ts --axios --responses \
  && node scripts/format-api-docs.js
```

After the backend endpoint ships and Swagger reflects it, running `yarn api:generate` adds a
`getPopularArticles` method and a `PublicGetPopularArticlesResponse` type to
`src/shared/infrastructure/api/generated/116.api.ts`. Expected generated signature (mirrors
`getPublishedArticles`):

```typescript
getPopularArticles: (
  query?: {
    limit?: number;       // @default 5
    categoryId?: string;  // @format uuid
    excludeId?: string;   // @format uuid
  },
  params: RequestParams = {},
) => this.request<PublicGetPopularArticlesResponse, ProblemDetails>(...)
```

## 2. Repository port + method

Port: `src/modules/articles/application/repositories/articles.repository.port.ts` — add:

```typescript
/**
 * Fetches the most popular published articles, ranked by engagement.
 *
 * @param query - Limit plus optional category and exclude-id filters.
 * @returns `ok(IArticleSummaryEntity[])` on success, `err(Failure)` on failure.
 */
getPopularArticles(query: IPopularArticlesQuery): Promise<Result<IArticleSummaryEntity[]>>;
```

Query shape (new interface in the same file, mirroring `IPublishedArticlesQuery`):

```typescript
export interface IPopularArticlesQuery {
    limit?: number;
    categoryId?: string;
    excludeId?: string;
}
```

Implementation:
`src/modules/articles/infrastructure/repositories/articles.repository.impl.ts` — add
(mirrors `getPromotedArticles`, which returns a bare `articles` array):

```typescript
async getPopularArticles(query: IPopularArticlesQuery): Promise<Result<IArticleSummaryEntity[]>> {
    try {
        const response = await this.api.getPopularArticles({
            limit: query.limit,
            categoryId: query.categoryId,
            excludeId: query.excludeId
        });
        return ok(response.data.articles.map(ArticlesMapper.articleSummaryFromDto));
    } catch (error) {
        return err(ProblemMapper.toFailure(error));
    }
}
```

The response wraps `articles: ArticleSummaryDto[]`, so the existing
`ArticlesMapper.articleSummaryFromDto` maps each element unchanged — no new mapper needed.

## 3. Use case

`src/modules/articles/application/usecases/getpopulararticles.usecase.ts` — mirrors
`GetPublishedArticlesUseCase` (thin wrapper, returns the repository `Result` unchanged):

```typescript
import type {
    IArticlesRepositoryPort,
    IPopularArticlesQuery
} from "@/modules/articles/application/repositories/articles.repository.port";
import type { IArticleSummaryEntity } from "@/modules/articles/domain/entities/IArticleSummaryEntity";
import type { IResultUseCase } from "@/shared/application/usecases/IUseCase";
import type { Result } from "@/shared/domain/results/result";

/**
 * @interface IGetPopularArticlesUseCase
 * @extends {IResultUseCase<IPopularArticlesQuery, IArticleSummaryEntity[]>}
 */
interface IGetPopularArticlesUseCase
    extends IResultUseCase<IPopularArticlesQuery, IArticleSummaryEntity[]> {}

/**
 * Use case for fetching the most popular published articles.
 *
 * @class GetPopularArticlesUseCase
 * @implements {IGetPopularArticlesUseCase}
 *
 * @description
 * Fetches the engagement-ranked popular articles. Delegates to the articles repository and
 * returns its `Result<IArticleSummaryEntity[]>` unchanged.
 */
export class GetPopularArticlesUseCase implements IGetPopularArticlesUseCase {
    private readonly articlesRepository: IArticlesRepositoryPort;

    /**
     * @param {IArticlesRepositoryPort} articlesRepository - Repository for articles operations (injected)
     */
    constructor({ articlesRepository }: { articlesRepository: IArticlesRepositoryPort }) {
        this.articlesRepository = articlesRepository;
    }

    /**
     * Executes the get popular articles use case.
     *
     * @param {IPopularArticlesQuery} query - Limit plus optional filters
     * @returns {Promise<Result<IArticleSummaryEntity[]>>} `ok(list)` on success, `err(Failure)` on failure
     */
    async execute(query: IPopularArticlesQuery): Promise<Result<IArticleSummaryEntity[]>> {
        return this.articlesRepository.getPopularArticles(query);
    }
}
```

Register in DI:
`src/modules/articles/infrastructure/dependencies/articles.dependencies.ts` (transient, like
its siblings):

```typescript
getPopularArticlesUseCase: asClass(GetPopularArticlesUseCase).transient(),
```

## 4. Rewire the `useArticleDetailPopular` hook

The hook (planned at
`src/modules/articles/presentation/hooks/useArticleDetailPopular.ts`) currently — per the
sidebar doc — calls `getPromotedArticlesUseCase` with a `getPublishedArticlesUseCase`
fallback and filters the current article client-side. Replace that with a single call to the
real endpoint, passing `excludeId` so the server drops the current article:

```typescript
export function useArticleDetailPopular(currentArticleId: string, categoryId?: string) {
    return useQuery({
        queryKey: articleKeys.popular(currentArticleId, categoryId),
        queryFn: async () => {
            const result = await container.cradle.getPopularArticlesUseCase.execute({
                limit: 5,
                categoryId,
                excludeId: currentArticleId
            });
            if (!result.ok) throw result.error;
            return result.value;
        }
    });
}
```

Notes:

- `excludeId` moves to the server — the client no longer post-filters the current article.
- The `getPromotedArticlesUseCase` fallback is dropped for the primary path. If the product
  wants a graceful fallback when the popular list is empty (a brand-new site with no
  engagement yet), keep a fallback to `getPublishedArticlesUseCase` **inside the hook** — the
  UI and mapping stay identical because both return `IArticleSummaryEntity[]`.
- Add a query key:
  `src/modules/articles/presentation/constants/articleKeys.ts`

  ```typescript
  popular: (articleId: string, categoryId?: string) =>
      [...articleKeys.all, "popular", articleId, categoryId ?? null] as const,
  ```
